## Pattern matrix seeds

One `random.Random(seed)` per pattern name, threaded through both sizes
(16×16 then 33×17, in that order; `flat` additionally does 1×1 last) in
a fixed loop order — reseeded only at the start of each pattern, per the
work package spec ("random.Random(seed) per pattern").

| pattern | seed |
|---|---|
| hgradient | 1001 |
| vgradient | 1002 |
| checker8 | 1003 |
| noise | 1004 |
| flat | 1005 |
| fewcolors | 1006 |
| photo (JPEG source) | 1007 |
| checker_anim.gif | 1008 |

`hgradient`/`vgradient` are deterministic ramps needing no randomness (the `rng` parameter is accepted but unused, to keep a uniform pattern function signature).

Sizes: 16×16 and 33×17 for every pattern × mode (l, la, rgb, rgba, p); 1×1 only for `flat` (the only pattern that isn't visually degenerate at a single pixel — checker/gradient/noise/fewcolors would just look like `flat` there too, so those combinations are skipped).

P-mode images additionally get a `<name>_transparency.{praw,png}` variant: same index grid, palette alpha `(i*53+29) % 256` per index `i`, written as a PNG tRNS chunk.

`.bmp` is generated for `l`/`rgb`/`p` only, **not** `rgba`: Pillow's own 32bpp BMP writer never declares an alpha bitmask, so Pillow's own reader (and any conformant BMP reader) opens the result back as plain `RGB`, silently dropping alpha — verified empirically. An RGBA BMP fixture would be an "exact" oracle for data Pillow itself cannot round-trip, so it's skipped. `.gif`'s global color table must be a power-of-two size, so Pillow zero-pads P-mode palettes on write; `crosscheck.py` accordingly only requires the *first* `len(truth palette)` GIF palette entries to match, not the padding.

## JPEG photo pattern

`photo_rgb_64x64` — smooth diagonal RGB gradient (`x`, `y`, `x+y` ramps) plus `randint(-2, 2)` per-channel noise, seed 1007. Encoded at quality 10/75/95. JPEG is lossy — `crosscheck.py` compares by PSNR (≥ 30 dB) against `photo_rgb_64x64.praw`, not exact bytes. Size and noise amplitude are tuned so quality-10 clears 30 dB with margin — a tiny image or stronger noise pushes even quality-10 JPEG below the threshold on pure block-quantization loss alone (verified empirically; see the generator's docstring).

## Animated GIF

`checker_anim.gif` — 3 frames, an 8×8 checkerboard (seed 1008 for its two colors) shifted 3px horizontally per frame. No `.praw` truth (multi-frame; `crosscheck.py` skips files with no matching golden with a warning) — exists to exercise multi-frame GIF decoding.

## zlib corpus (`tests/golden/zlib/`)

Each data class `<class>` is written as `<class>.bin` (raw), `<class>.z0` … `<class>.z9` (`zlib.compress(data, level)` for level 0–9), and `<class>.raw9` (`zlib.compressobj(9, zlib.DEFLATED, wbits=-15)` — a raw, headerless deflate stream at level 9).

| class | size | seed | notes |
|---|---|---|---|
| empty | 0 B | — | |
| one | 1 B | 2001 | |
| zeros | 4096 B | — | all `\x00` |
| random4k | 4096 B | 2002 | |
| text | 20480 B | — | repeated English paragraph (see script) |
| b65535 | 65535 B | 2003 | one byte short of the 64 KiB DEFLATE stored-block boundary |
| b65536 | 65536 B | 2004 | exactly the 64 KiB boundary |
| random100k | 100000 B | 2005 | **trimmed from the spec's suggested 200 KB** — random data is incompressible, so all 12 variants (bin + 10 levels + raw9) cost ~the full size each; 200 KB would have used ~2.4 MB alone. 100 KB keeps `tests/golden` comfortably under the ~4 MB budget. |
